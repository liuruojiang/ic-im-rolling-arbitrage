# 免费源接入、真实 IC 原日验收与只读采集

## 结论与边界

本轮按“接入已验证免费源 → 真实 IC 原日录制/隔离落账/历史回放 → 累计测试和多智能体复审 → 本机只读采集”执行。正式账户保持 2026-10-21、sequence 19；研究副本推进到 2026-10-22、sequence 20，不据此续写正式账户。

- 最终累计 101 个测试文件、2918 项通过、原 22 项单列不变。1012 份绑定文件在运行前后及最终核验时一致；原第五轮 19 项包含在内。
- 本轮新增 8 个测试文件、152 项，涵盖免费源、市场身份/日期、历史路径、严格回放事实契约、有限并行采集、并发存证、采集入口与新浪实际线缆格式。三路多智能体审计及最后参数/部署复审均已完成，所发现问题已处理；不冒称完整安全审计。
- 真实 IC 原日包通过：实际时钟、无合成行情，持有独立核心 510500P2612M06500 / 10012149 / 15 张；原日 IC/IM 合格信号按正常规则写入隔离账本，再在保留 historical_replay 的情况下回放 IC。EvidenceUnavailable=0，底层 HTTP 请求=0；原日 URL 集合非空，回放请求集合为其子集；全部原日事实字段一致。
- 整个字典仍有明确差异：三个计算时刻、close_confirmed→retrospective_replay 的生成语境转换，以及 original_evidence / historical_evidence_supplements。它们由单独的严格契约验证，其余字段不允许删除、增添或变更；完整差异保留，不以“除时间戳外完全相等”概括。
- 只读采集器已本机启动并验证存活、排他锁及实际首轮回执。首轮 IC 完整、IM 的 MO 复核代理超时；第二轮于 18:41:08 自动重试结束，IC、IM 均 captured，真实 MO 缺口补齐。delivery/deployment_acceptance.json 核验了五分钟自动重试，不完整旧包仍保留。

## 本轮生产变更

1. `poe_ic_im_mainline_v1_4_bot.py`：ETF 现价/昨收接入 SSE→腾讯→新浪严格回退；挂牌月份增加新浪实际月份回退并核对挂牌形状。新浪 Put 明细每批 6 个、最多 2 个并发；OP_DOWN/CON_OP 变量必须精确、完整、无重复。保留 M/A 隔离、合约完整到期日、20 分钟选中报价门控，不伪造日期或成交。确切新浪端点将安全 CSV list 按字面逗号发送，逻辑存证键仍为原 URL+dict。
2. 同一构建复用经过标准化并核验的月链，缓存范围受请求日、回放/会话身份约束；采用实际经过时间校验实时采集，不把正常新刷新误判为未来。原日 IV 监测结果作为独立具名输入存档，回放保留原有 N/A、来源和校验时钟。
3. `ic_im_evidence_adapter_v1.py`：独立采集最多 4 个任务并行，复制 ContextVar，预取实际观察到的挂牌月份；同品种仍配置 45 秒预算，传输失败至多重试一次，结束前等待写入并统一检查完整性/冲突。第三方库自己的固定 timeout 不能宣称绝对墙钟 45 秒上限。
4. `ic_im_signal_evidence_v1.py`：存证锁保护归档变更，独立输入并行，同 role/key 合并；结束时拒绝仍在写入的会话。嵌套同线程旧 wrapper 只记录外层验证结果，避免孤立 blob/重复总量。原始响应歧义、完整性和来源校验保持严格。
5. 新增 `capture_ic_im_v1_4_inputs.py`：只读既有迁移账本，收盘后独立原日采集；5 分钟循环、文件排他锁、源码 SHA 固定、回执，临时锚点在 finally 恢复。没有 server 导入、初始化、正式续账或发消息。代码变更由 delivery/source_delta.patch 和 final_verification.json 绑定。

## 部署与保护核验

新证据在 `data/icim_v14_original_inputs`，正式账本在 `runtime/ic_im_v1_4_r1`，两棵目录分离。28 文件 source pin 覆盖采集入口的全部 16 个本地依赖。首次启动发现漏绑 im_put_policy.py 后立即停止，保留旧 pin/停止原因；补齐 pin 后重新启动。当前 PID、启动时刻、实际回执、重复进程退出码和校验和以 delivery 机器回执为准。

新进程是本机隐藏采集器，需要电脑持续运行。未建立重启后自启、云端常驻或远端 Poe 已更新的保证。标准任务计划/进程全量查询权限不足不影响已启动进程自身的 Get-Process 检查。后续查询和补录必须使用交接中的 ICIM_EVIDENCE_DIR；不能假定旧服务默认目录已经连通。

baseline 的 9114 个保护对象中，3 个预先备份的生产模块及主线登记文档按上述范围改变，其余 9110 个不变；6 份备份核对通过。正式 runtime 全部 156 文件的集合及字节不变。生产状态存储/server 源码、保护的历史产物未改；旧规范和失败回执保留。
