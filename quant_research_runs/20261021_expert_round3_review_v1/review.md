# v1.4 第三批修订复查：结论与下一轮边界

日期：2026-10-21。范围：当前工作区源码及依赖的只读复查、多智能体交叉检查、离线公共入口反例。**本轮尚未修改生产代码，以下问题不计为已修复。** 不修改正式账本，不替换前轮测试回执。

## 结论

这轮反馈揭示了真实的恢复缺口，不能再用“仅待补齐日历”描述状态。诊断不写账的边界应保留；应修复的是原日证据保存、恢复路径和非必要依赖造成的阻断，而不是允许跳日落账或将估算到期日充当正式目标。

采纳独立证据存档方向，但“仅遇到 calendar_unverified 才抓几份报价”不足以承诺恢复。采集应独立于账本推进，历史读取必须真正接通且通过既有验证；没有原日合格证据就明确报告缺失，不能用当前链替换。

## 已确认与需更正

| 项目 | 复查结果 | 下一轮处理边界 |
|---|---|---|
| 诊断后账本冻结 | 成立。桥接只允许首个未核验交易日；统一账本要求 IC/IM 同日共同成功 | 保留逐日推进，补齐可验证的恢复路径；一腿阻断会影响整个共同账本 |
| IC 历史月换补录 | 成立，历史 ROLL 被无条件拦截；仅补日历不会解除 | 原日证据读取器接通后再有条件解除；缺证时继续阻断 |
| 卖 Put 每日候选探测 | 成立，宽异常边界会污染整个组合 | 先判断候选是否实际被策略消费；确定不会消费时跳过。实际需要的候选数据未知，不等于已确认未挂牌 |
| 跨年比较拦截 | 部分成立 | 对具体谓词证明结果不变，不能只加 purpose 参数全面豁免；目标交付、数量、调度仍有独立检查 |
| 诊断参考信息缺失 | 成立 | 增加已成功算出的动量、网格和换仓参考信息，明确未确认，不能变成正式目标或新计划 |
| 网格未确认仍可落账 | 公共 builder 和存储检查均复现 | 生产端与存储端统一要求网格确认；不能仅相信 signal_complete 自报值 |
| 快照读取竞态 | 公共查询入口复现 | 同一 RLock 内读取并 deepcopy，释放锁后渲染；单独 deepcopy 不足 |
| 未知日历导致整条查询失败 | 2027-01-04 16:00 公共默认查询和收盘信号入口复现 | 构建号降级并保留最后核验快照；测试覆盖真实 run 路由 |
| Put 策略吞掉传输异常 | 成立 | 必需的持仓、核心腿证据异常回到既有外层重试；候选探测单独划边界 |
| numpy 导出类型 | 复现 bool/int 变成字符串 | 转为原生布尔和整数，保持 JSON 类型 |

反馈中以下推断需要收窄：

- “IC 11-20 必然诊断”不能脱离仓位状态下结论。正常实时选约函数在目标 Delta 为零时提前返回；但当前历史 ROLL 硬拦发生得更早，仍需修复。具体冻结日期须用连续状态回放确认。
- IC 补录失败不是只能人工锚定。接入原日可信归档或合格的外部历史证据后，可按正规路径重放；人工锚定不作为默认修复。
- 服务端已有连续补录机制。max_sessions=4 是单次调用上限；后台每 300 秒尝试推进一天。问题是首个缺口无法通过，不是缺另一套定时器。
- 当前 quarter_roll.roll_state 没有吞掉 CalendarCoverageError。季度执行日真实依赖未知年份时，仍会独立阻断，不能承诺放开纯比较后某段日期全部正式。
- 维护提醒的 _valid_maintenance_day 已捕获日历异常并返回 False。默认收盘查询整体失败的已复现位置是构建号生成中的最近已完成交易日检查；提醒仍可改善“为何跳过”的解释，但不是同一个异常传播问题。
- select_active_future 包含筛选和排序，不能整体视为纯比较。对于不变持仓的放行还必须绑定可信账本锚点，核对身份、数量、无新增计划；不能依靠 signal 自报 current 字段绕过交付和存储检查。

## 证据存档方案：采纳的最小要求

1. 在适配器收到原始响应时存证，优先复用已取得的数据。记录原始字节、来源、请求参数、来源交易日和时间、真实获取时间、解析版本及 SHA-256。追加写入、内容寻址、原子 manifest；哈希只证明完整性，不代替日期、身份及来源验证。
2. 采集不依赖正式信号成功或账本推进。否则首个缺口后续查询在取数前就被阻断，之后的维护日仍没有证据。额外采集设置独立预算，明确完整度和失败角色。
3. IC 月换至少需要原日挂牌月份、所需候选的完整标准 M 型 Put 链、证券 ID/交易代码/行权价/单位/到期身份依据、ETF 和期货报价；同时保存持仓及待执行各腿的身份、报价、适用开盘证据。只保存最终合约不够复原选约。不得推断 A 型合约身份。
4. 同时绑定 MO、OHLCV、估值、恐慌和实际使用的利率模式/数值/源日期/可用时点，以及策略版本、决策时点和原锚点摘要。IC 历史卖 Put 候选目前也不可用，须接通档案，不能将其造成的不准入冒充原日决策。
5. 历史读取器只读取目标日合格证据，继续通过日期、身份、数值、日历、策略和 StateStore 验证，再逐日推进。缺失时列出日期和角色，不转用当前链、不伪造获取时间、不跳日。
6. 明确回放口径：现有 close_clock 是 15:20，而中债官方模式要到 17:30 后才可用。15:20 补录不能声称复现原晚间官方利率下的相同数量；需保存并验证原合法决策时点，或明确按既定补录口径重算。

## 修订顺序

1. **P0：恢复闭环。** 冻结证据格式、独立采集和缺证诊断，接通历史读取器；验收 IC 月换与 IM 多日连续恢复。在闭环通过前不宣称自动恢复已完成。
2. **P1：消除不必要阻断。** 共享策略的非候选准入前提，跳过未消费的候选；对不变比较给出局部证明。实际选约、数量和调度保持严格核验。
3. **P1：交付与展示可信度。** 网格双端门控、快照同锁读取、未知日历下公共入口降级、诊断参考信息。
4. **P1/P2：重试和小修。** 必需证据传输重试、numpy 类型、错误注释和不可达分支说明。
5. **进一步分析。** 连续 2026-10-15 至 12-31 的完整状态回放；真实盘中开盘日线与开盘前 SSE 报文 oracle；网络持锁的服务容量影响。合成组件矩阵不能代替这些验收。
6. **暂缓。** 独立性能重构、代理估值清理、重复代码和无关版本文案，不混入本轮恢复修复。Put 换月研究候选继续不进入正式策略。

## 本轮证据与限制

- reproduce_display_review.py 与 display_review_repro_receipt.json：16 项反例及边界断言通过，退出码 0；16 个绑定源文件（含复现脚本及所用 fixture 模块）前后哈希一致。这里的“通过”表示反例成功复现或边界确认，**不表示缺陷已修复**。
- display_grid_public_probe.json：公共 run 在未知年份下的输出；公共 builder 的网格未确认结果；持久化门控、网格校验、完整交付校验仍通过；numpy 导出类型。
- snapshot_concurrency_public_probe.json：受控开盘投影窗口内，公共快照错误显示临时锚点；同锁复制会等待并读回原锚点，builder finally 正常还原。
- 合成输入用于隔离反例，不是实时接口验证，不是连续完整账本回放，也不证明专家表中每个触发日期。前轮通过的 2025 项测试只代表当时覆盖范围，不作为本轮新问题已经修复的依据。

代码依据：bot 的单日桥接、IC 历史 ROLL 硬拦、日历上下文与最终交付标记；state 的共同逐日推进、资格和网格校验；server 的现有补录调度；policy 的准入与持有卖 Put 移仓状态；quarter_roll 与 maintenance notice 的实际异常边界。独立子任务未修改生产代码或正式账本。
