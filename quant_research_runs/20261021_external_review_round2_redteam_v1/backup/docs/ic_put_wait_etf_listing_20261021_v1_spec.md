# IC等510500 ETF期权新月份挂牌后收盘换Put v1

2026-10-21，结果前预注册。用户认为IC不应照搬IM周一挂牌日历，应持有旧Put直到ETF新月份实际挂牌，再卖旧换新，以维持较长期限。只测试研究候选，不改正式版本或旧输出。

1. 同已核验IC fix11反事实完整账户：真实挂牌期2022-09-19—2026-08-13；核心0.5倍、动量、Fear25/50来源配对网格、卖Put及三倍兑现、无Call、期货每倍30%缓冲、费用/现金全部继承。对照baseline与前次原结算日信息冻结/周一收盘组。
2. 原期货月度维护结算日（通常周五）冻结风险信号、保护目标和ETF价格/95%行权价锚点；保留旧Put，普通风险退出与卖方/恢复路由优先。等待相对原结算日真实行情面板新增一个到期月份，不把新行权价或成交量变化当成新月份。
3. 对每个待维护事件，逐日检查已观测的510500标准Put月份集合；只有实际原始合约面板已出现新增月份，才于该日收盘维护。不是固定周一、也不硬编码第四周四；节假日按真实面板/共同交易日处理。首次出现日期是历史重建面板证据，不冒称全历史交易所时间戳挂牌认证。输出与交易所月度规则日历的偏差核查。
4. 两个独立候选：wait_nearest保持原执行日+3个日历月、实际挂牌到期日最近规则；wait_min3在同一挂牌日增加“到期日不得早于执行日+3个月”的筛选，选择满足的最近到期日。后者用来真正实现买入时不少于3个月，不能把等待挂牌本身当作该期限保证，也不默认买最远新挂牌季月。
5. 核心与独立动量买Put同步维护。保护风险目标与行权价锚点继续冻结原结算日；新合约实际权利金、IC Delta、资金规模在执行日收盘计量。所有旧/新两腿须有同日真实正收盘价，否则整次留旧并保持冻结信息，下一真实交易日收盘重试。旧合约先到期仍按继承结算规则，不制造不存在的保护。
6. 买入期限下限只应用本次月度延期维护；普通新进入/风险数量调整/三倍兑现保持旧规则。报告应分别披露维护买入时期限，以及持有期期限递减；不得把“买入不少于3个月”说成所有交易日恒有不少于3个月。
7. 先逐日、逐笔复现旧baseline与周一冻结组，再独立候选。输出全期/3年/1年收益风险、挂牌等待映射、每笔选约目标/实际期限、新挂牌月份、缺价、真实成交边、未完成待办。特别核查2023年1月与2月，旧样本中曾反复选择3月Put。
8. 独立复核账本NAV/费用/回撤、全部延期维护真实收盘证据、信息日冻结、实际月份新增，以及min3下限。动态日历不提前访问未来行。原始数据/旧脚本/输出/正式账本先备份和SHA保护。
9. 继承ETF重建合约主表、原合约到期日近似、后下载Fear、模型分数数量、普通填价等限制。执行日+3个月以原冻结引擎的到期语义比较，另核对休市顺延不会破坏min3。日线同收盘成交为理论假设，不证明尾盘双腿可成交。仅研究，未获实盘授权。
