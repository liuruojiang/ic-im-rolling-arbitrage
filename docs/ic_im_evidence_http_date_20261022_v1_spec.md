## 已知反例与边界

上一轮 time_probe_02 的真实 SSE 510500_12 响应，两次正文 SHA-256 与行情 date/time 完全相同，HTTP Date 相差 11 秒。RFC 9110 §6.6.1 定义 Date 为消息生成时间；§8.8.2 定义 Last-Modified 为资源最后修改时间。当前策略与新鲜度代码不读取 HTTP Date，但会读取 Last-Modified，因此不能一概忽略响应头。

## 本轮唯一生产行为变动

仅精确匹配 https://yunhq.sse.com.cn:32042/v1/sho/list/tstyle/510500_MM（MM=01..12）的响应，在同请求的一致性比较中不使用 Date 头。其余响应头、正文哈希、状态、解码编码、请求参数与其他地址的规则保持严格。录制和读取共用比较函数，全部原始 Date 仍逐次保留于哈希保护的清单。读取保持现有的最后一个等价观测规则，绝不按 Date 推造行情时间。正文 date/time 的任何改变依然是冲突，不放宽交易日、新鲜度或收盘确认。

不新增通用 URL 网络缓存，不把 Date 充作报价时刻，不解除旧不完整包的失败，不使诊断信号落账。策略/日历/历史回测公式与正式账本保持原状。代理诊断只使用既有代理与授权网络路径，不关闭 TLS 或绕过网络限制。
