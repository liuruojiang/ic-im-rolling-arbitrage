## 入口

长期运行入口改为`poe_ic_im_v1_2_server.py`，通过Poe Server Bot的Server URL接入。托管服务必须把`ICIM_STATE_DIR`挂载到持久卷；`poe_ic_im_v1_2_state.py`负责原子写入`latest.json`和只增不改的哈希链日志。`Dockerfile.poe-v1.2`是标准部署入口。

`poe_ic_im_mainline_v1_2_bot.py`仍保留单文件本地/Poe代码测试兼容，但它没有跨进程持久存储和收盘定时器，不再作为长期生产查询入口。只把该文件复制到无状态代码编辑器，会在静态审计锚点后的后续日期再次停机，这是运行形态限制，不是可接受的日常部署。

“信号”与“实时信号”标题固定显示构建号`v1.2-20260825-r16`。Poe输出若没有该构建号，表示Server URL仍指向旧部署。

## 信号输出顺序

`信号`与`实时信号`都按以下顺序输出每个品种：

1. 当前总期货、下一交易日目标和净变化；
2. 0.5倍裸滚核心袖；
3. 0.5×动量权重袖；
4. 独立估值网格；
5. 三条期货腿汇总；
6. Put与Call；
7. 动量Score、Abs20、信号日和执行日；
8. 期权覆盖边界及数据时点。
9. Put总张数按裸滚核心袖、动量指引袖和网格逐项拆分，并说明合约选择理由。

估值必须显示为文字档位，不能用“0倍估值”描述。基础观察档表示尚未跨过第一条Put保护阈值；表格中的0倍只表示独立网格当前没有仓位，不代表估值等级。

当前仓位是从截至2026-08-14的本地审计账本按规则续接出的研究仓位，不是用户账户持仓。8月21日到期月换与8月24日逐腿重放均已计入审计锚点，不再误报为下一交易日动作。

2026-08-24现在只是持久化账本的首次启动检查点，不是代码中的永久“最新日期”。Server Bot每个交易日收盘后把IC/IM期货、Put、Call、动量和网格同时推进一日；次日进程重启时从持久卷读取最新核验日。只有两个品种均完整成功才写入新序号，任何半成功结果都不更新`latest.json`。

若联网行情失败，仍可只读显示持久化账本中的最后逐腿核验快照。首次启动检查点为2026-08-24（IC/IM当日收盘期货合计均为1倍；IC 14张`510500P2612M07500`，IM规范化1.5张`MO2612-P-7200`且Call为0）。联网失败时不生成新的下一交易日目标，也不推进哈希链。

## 收盘与盘中语义

- 已完成交易日：输出下一交易日确认目标。
- 当日盘中或收盘尚未确认：输出下一交易日预估目标，并明确要求等待收盘确认。
- 动量袖：T日收盘权重在下一共同交易日形成实际研究仓位。
- 网格：T日收盘信号，T+1开盘执行。
- Put/Call：T日收盘评估，T+1收盘执行。

所有实时价格和历史价格必须为有限正数；历史至少覆盖最近已完成交易日。NaN、无穷值、非正价格、未来日期、陈旧日期或ETF/期权链日期不一致时，不降仓、不撤保护、不推导替代目标，而是暂停该品种新增/调整信号。IC+IM双品种联网查询总上限为90秒，每个品种获得45秒独立子预算；单品种也保持45秒上限。子预算不能延长父截止时间，避免前一品种或单一数据源耗尽后续备用源预算；截止时间保存在请求上下文中，并发查询之间不得共享或覆盖预算。

实时新鲜度和信号入口只接受已载入官方休市表的年份。当前仅覆盖2026年；2027年及以后在相应官方日历加入前直接`fail-closed`，不得把普通工作日冒充正式交易日，也不得进入无界日期回滚循环。挂牌到期日的研究展示仍可附带“仅按工作日估算”的覆盖提示，但不能绕过实时信号闸门。

中金所实时与历史下载只允许HTTPS，绝不因TLS失败回退明文HTTP。月度ZIP设置8MiB下载、128成员、单成员8MiB和总解压96MiB上限；超过任一上限或包含加密成员即拒绝处理。中金所延时CSV使用HTTPS响应`Last-Modified`作为源文件时点；缺失或非法时该源失败并进入备用源，不用HTTP `Date`冒充交易所行情日期。即使验证成功仍是延时研究行情，而非可下单盘口。

### r10多源行情容错与挂牌完整性

- IC/IM期货按“中金所官方HTTPS → 新浪财经期货节点 → 东方财富中金所列表”顺序尝试；MO期权链按“中金所官方HTTPS → 东方财富全CFFEX期权链”顺序尝试。中金所官方源单次最多4秒，新浪/东方财富单源最多8秒；若进入行情链时剩余预算不足14秒，跳过中金所官方源并把剩余时间优先留给备用源，目标预留10秒。主源成功时仍在剩余预算内请求备用源作交叉审计。
- 所有适配器统一输出`instrument/lastprice/bprice/sprice/volume/position/source/source_date/source_time`。合约必须完整匹配IC/IM四位年月或MO标准代码；缺关键列、非法代码、重复合约、负成交量/持仓、未来日期或陈旧日期均拒绝整个来源。原始挂牌行在剔除无成交/非正价行之前先统一校验日期，禁止让NaN行携带的冲突日期被静默过滤。东方财富的`utime`只称“供应商更新时间”，不解释成交易所成交时间。
- 挂牌结构只按每个来源自己的`source_date/as-of`计算，不使用周末查询时钟替代。IC/IM必须精确包含当月、下月及随后两个季月，共4个互异合约；到期日当天仍含当月，下一交易日才前移。MO必须精确包含当月、下两个月及随后三个季月，共6个月。规则依据中金所[中证500期货合约](https://www.cffex.com.cn/cn/zz500.html)、[中证1000期货期权上市说明](https://www.cffex.com.cn/cn/ssxz/20220718/43093.html)及[中证1000股指期权合约](https://www.cffex.com.cn/zz1000gzqq/)页面。
- MO挂牌完整性按原始标准合约代码核验，必须保持上述6个月结构及每月Call/Put行权价对称；无有效正价的未成交远端合约只从可选报价子集中剔除，不能因此误判为未挂牌。最近月、当前旧腿和实际目标候选仍必须有有限正价；只有2609/2610等两月的残链不得参与选约。
- 两个来源同时可用时，as-of日期必须相同；IC/IM标准合约集合必须严格一致，MO到期月集合必须严格一致，并须存在足够逐合约交集。期货共同合约若价格同时偏离超过10点和1%即严重冲突；MO共同合约中位相对偏差超过3%或90分位超过15%即严重冲突。任何日期、集合或价格冲突统一`fail-closed`。
- 当东方财富MO链被采用时，对实际参与Put重置或Call D10/救援判断的合约，再请求新浪单合约详报价；独立核验合约日期、有限正价、成交量、持仓及价格偏差。当前实测两个host的共同报价一致，但可能共享底层行情feed，因此只能算跨host复核，不能宣称独立交易所双源。
- 信号输出必须显示实际采用的`source`、`as-of`、跨源审计结论以及每个失败来源的汇总原因。不得只显示“中金所失败”。

### r16持久化逐日续接与自愈

- 每个持久化记录包含`schema_version/sequence/verified_day/previous_digest/digest/products/signals`。SHA-256覆盖除自身`digest`外的全部内容；写入顺序为新日志文件后原子替换`latest.json`，防止中断留下半写文件。
- 账本只能从上一核验交易日推进到严格下一官方交易日；IC与IM必须同日、收盘确认、全部腿成功。部分品种成功、日期跳跃、摘要损坏或并发旧写入均`fail-closed`。
- 服务进程每5分钟检查一次，收盘后自动推进；一次成功的普通`信号`查询也通过同一个观察器写入。进程重启后先读取持久卷，不依赖聊天记录或源码日期。若收盘任务漏跑，服务逐交易日补账；历史行情不足以复原某个状态切换时暂停而不猜测。
- 当前腿直接从上一核验日账本及其已确认目标推进，不能用当日价格倒推。盘中行情只形成下一交易日预估目标；收盘确认后才允许写入审计链。
- IC非月换日保护档变化时，沿用已审计合约，用当日ETF、期权和期货有效价格反解IV/Delta后重算张数；月换日才重新按规则选期限和行权价。任何无法反解或旧腿缺价的情况都不写账。
- IM Call在账本中保存合约、到期日、行权价、规范化数量和连续救援次数；`rescue_next_listed`仍是严格晚于旧到期日的最近实际挂牌期限。IC Call字段必须始终为0。
- 腾讯指数现价改用含时间戳的完整报价；桥接时指数、期货、ETF、510500期权链及MO链的可验证行情日期都必须等于北京时间当日。东方财富无可验证时间戳的指数现价只能作为非桥接场景备用，不能伪装成当日盘中价格。
- 挂牌结构按供应商返回的完整代码集合验证；有限正价子集用于执行。远月暂未成交可以没有最新价，但月换必须按行情日先从挂牌集合确定严格下一期货，不能因周末查询时钟或次月无价跳到季月。MO Put先按挂牌集合确定规则期限及约95%精确行权价；救援先确定严格下一挂牌期限及满足上移5%的最低挂牌行权价，精确合约无价即停止。D10先固定严格下一挂牌期限，再仅在该期限内对具有有效价格、成交、持仓且可计算IV/Delta的合约择优；不会跳到更远期限。
- 2026-08-21已经完成的Put月换不会在后续逐日续接中重复调用选约器；只有规则月换日才重新选约。

### 一次性部署要求

1. 在托管平台构建`Dockerfile.poe-v1.2`，将`/data`挂载为持久卷；至少保留一个常驻实例，不能使用每次请求都丢弃磁盘的无状态函数。
2. 在平台密钥管理中设置`POE_ACCESS_KEY`，不要写入源码、镜像或日志；本地可用`.env.schema`配合Varlock校验。
3. 部署后先访问`/healthz`，必须看到`status=ok`、`verified_day`、递增`sequence`和`digest_prefix`。
4. 在Poe创建/更新Server Bot，把Server URL指向该服务根地址。以后更新代码只需重新部署，持久卷不可删除。
5. 每个交易日收盘后监控`verified_day`是否推进；`status=degraded`或日期落后时告警，但不得自动清空或重建账本。

官方推荐路径可直接使用`modal_poe_ic_im_v1_2.py`：

```powershell
python -m pip install -r requirements-modal-deploy.txt
modal setup
modal volume create poe-ic-im-v1-2-ledger
modal deploy modal_poe_ic_im_v1_2.py
```

在执行`modal deploy`前，由操作者在Modal网页控制台的Secrets页面创建名为`poe-ic-im-v1-2`的Secret，并在网页中填写`POE_ACCESS_KEY`；不要把真实值放入命令、聊天、源码或仓库。

Modal定时函数是唯一写入者，在工作日北京时间15:20至18:50每30分钟重试一次；账本已是最新日期时为空操作。Web实例每次读取前`reload` Volume且保持只读，并限制为单容器；定时函数成功推进后立即`commit`，避免定时任务与查询并发形成分叉写入。

日常巡检、告警处置、升级和回滚步骤见[POE 1.2运维手册](poe_ic_im_v1_2_operator_runbook.md)。

## 1.2 特有边界

- IC：核心袖使用完整V2 Put；动量袖只使用估值Put；网格不加Put；无Call。
- IC Put输出先显示估值档目标，再显示MOM120下限。核心袖两者取较大值；动量袖先由Score+Abs20决定是否持仓，有仓时仅应用估值档，空仓时Put为0，不继承MOM120下限。最后分别列出两个袖的Delta贡献与主导原因。
- IC先显示估值数值与文字档位，紧接着显示该估值对应的Put Delta值。张数输出不展示冗长数学等式，只列出当前与下一交易日的标准化总张数，并拆成裸滚核心袖、动量指引袖、网格三部分；整数分摊必须严格加总到总张数。
- IM：Put与Call只覆盖0.5倍核心袖；动量袖和网格均不配置期权；负动量下限仍是父版本v1.1的每1倍3张，第4张只能由估值第4档产生。
- IM Put输出分别显示绝对估值轴档位、57个月相对估值轴档位、两轴较高目标、MOM120下限及最终主导原因。
- IM张数输出直接拆成裸滚核心袖、动量指引袖和网格；后两者固定贡献0张。文字说明估值档与MOM120下限谁主导核心袖目标。规范化小数张数不是可直接成交数量，实际账户仍须映射成整数。
- IC和IM都说明目标执行日+3个月、最近实际挂牌到期日及约95%目标行权价如何产生最终期权合约。
- IM网格为1.60/2.00，不使用冻结V2的0.85/1.25。
- 1.2绩效查询使用独立重组并内嵌的定值研究曲线，不复用或冒充V2收益。
