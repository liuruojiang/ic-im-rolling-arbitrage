# 同址报文冲突与封存落账边界 v1

2026-10-22 预注册，承接专家四点反馈。仅收紧输入证据一致性、落账门禁、失败展示与统计，不修改策略参数、估值/数量公式、日历内容或历史产物。

1. raw_response 当即检测同 URL+逻辑参数的 body/status/encoding/已有严格 headers 差异，记录永久未解决 raw_http_conflict；冲突本身不抛错、不取消普通 Response。I/O/大小/格式等真实录制错误继续抛错，不声称所有异常均可忽略。
2. 普通查询默认不启用 capture；显式 capture 中的信号在封存前 persistence_eligible=False。成功封存后只恢复原本合格的绑定信号，失败或冲突会话保持不合格并可展示参考计算值；StateStore 二次拒绝未封存/冲突标记，深拷贝的封存前信号同样不能落账。
3. 同址冲突不可在当前会话解除；后续相同报文也不修复已冲突包。完整重试必须使用新 CaptureSession。旧不完整包留存；has_original 的存在性路由不得误称可用：仅不完整时明确拒绝，且不能触发当前数据兜底；新完整包可被 load_original 选用。
4. 采集器仍每五分钟以新会话重试。单轮预算耗尽/失败不输出可恢复承诺；页面提示当日存证缺失，需另行补证或人工锚定。连接在取得响应前的有限重试不改变已有观测；已有报文冲突后不可在原会话重算放行。
5. 日统计按品种记录已封存采集尝试/冲突次数/请求数及分母，连续留存。只统计有记录的实际交易日，不能用单日零冲突推断收盘 time 永远稳定。
6. 本轮不新增通用 URL 网络响应缓存；已有具名输入/月链复用按上轮版本保留，明确其归属。
7. 日历注释改为 covered years，仅注释。

先保留修复前反例与源码备份；新增冲突/晚到冲突/深拷贝/未封存/成功封存/全新会话恢复/页面/统计测试，相关累计回归与旧22单列清单保持。旧 reader 纯解析单元测试如需构造故意损坏的内存 reader，应明确不通过正式 load_session，不放宽正式读取。测试和当前真实已部署包恢复均应通过；本机采集器源码变动时停旧进程，固定新SHA清单并重新启动，验证正式runtime及原有证据字节不变。旧规范和旧回执不改写。
