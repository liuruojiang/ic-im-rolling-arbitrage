预注册：2026-10-22 Asia/Shanghai。研究恢复验证，不扩大交易、邮件或正式账本授权。

## 输入与边界

采用本机独立采集器 2026-10-22 已部署目录 data/icim_v14_original_inputs 的真实 IC/IM 原日包；原始行情与时戳不合成、不后填。正式账本 runtime/ic_im_v1_4_r1 只读，复制后测试。固定当前 28 模块 SHA，并记录正式 runtime 全路径和字节。归档可新增后续回执，原有证据字节不可修改。

## 验收

1. 用 LedgerCoordinator.execute_query 的显式 historical_replay 读取两品种真实部署包，按正常持久化规则在副本恰好推进一个交易日。
2. 用真实服务端 catch_up_until_current 自动分支恢复同一交易日；仅调度控制时钟设为 2026-10-23 开盘前，属于明确标注的模拟调度，不声称真实未来交易日验证；所有市场数据仍为真实 10-22 包。
3. 二次补录幂等，账本不重复追加；恢复后 health 日期与序列一致。
4. 缺失 IC 包、IC 必需 blob 损坏、配置错误证据目录分别不能部分推进账本；不得用今日链冒充历史链。负例只修改研究副本。
5. 所有恢复阶段阻断外部 HTTP 并记录调用尝试，真实正例要求不依赖外网、不缺必需原日输入；如展示阶段另发请求，单独列出，不冒称全流程零请求。
6. 逐品种保存状态资格、原包 SHA、输出和实际落账记录，检查 signal_complete、persistence_eligible、非 diagnostic_only、非 calendar_provisional 以及无缺失原日输入。
7. 检查采集器实际存活、当前源码 pin、已成功包可由生产 EvidenceReader 全 blob 验证。确认现有配置是否真的采用新目录；只读/副本启动衔接应具体可执行。
