# 日报故障修复流程（2026-11-04 用户要求）

适用于 IC/IM、微盘股及其日报恢复、渲染和发送故障。目标是修好实际交付，只重做因本次变化而失效的阶段。此流程不改变策略参数、历史采用批准、来源/日期/成员/ST/raw-share/哈希链、盘中截止或发送去重边界。

## 1. 先定位失败阶段

先读取本次真实 run、退出码、错误、当前进程/锁和已有工件，沿“来源与恢复 → 数据准备 → 策略计算 → 整体检查与封装 → 渲染 → 发送 → 收件核验”找到最后一个可验证的成功阶段。文件存在、启动成功、mtime 或旧 stdout 不能证明完成。

同一工作区和发布目标只有一个执行者。已有修复仍在运行时，跟进其真实回执，不另开同入口、不更换其工作树分支、不覆盖其状态文件、不重复 dispatch。独立文档工作使用独立目录。

开始实施前，用简短说明或既有修复记录列明：失败点；本次改动；已通过且可复用的阶段；必须重做的阶段及理由；实际交付完成条件。普通小修不另造大型计划、缓存平台或额外审批。

## 2. 按影响决定验证和重算范围

| 故障/改动 | 修复与验证 | 复用范围 |
| --- | --- | --- |
| AGENTS、文档、交接说明 | 内容、编码、链接和差异检查 | 原测试、数据、策略结果和发送状态；不触发行情、pytest、整包重建或云端验收 |
| 邮件标题、正文、表格或渲染 | 原最终 CSV/result.json 的同次只读重渲染，受影响字段/身份/日期测试 | 合格当日输入、策略结果、已验证完整包；不重新取数或续账 |
| 恢复目录漏文件、传输或依赖装配 | 原失败反例、真实依赖闭包和篡改拒绝；同一原包经正式恢复器验证 | 未受影响的原始来源和策略经济数据；不因 Git SHA 变更就宣称所有数据失效 |
| 超时、连接中断、500/502/503/504 | 按原规则只重试失败请求/品种/阶段，次数有界；保留失败回执 | 已成功请求与计算；403/认证拒绝、结构损坏、错日、冲突不按临时网络错误重试 |
| 策略、成本、持仓或共享输入逻辑 | 原错误反例和受影响不变量；共享输入变化覆盖依赖的三版/两腿 | 依赖未变且身份可验证的其它模块；实际历史/ST/成员变化仍走原精确批准和必要重建 |
| SMTP 或发送回执失败/未知 | 先核原 run、intent、SMTP receipt、完成 marker 和实际收件，确定是否已发送 | 已验证报告与附件；不重新运行策略来重试邮件，不删去重证据，不另起发送通道 |

先跑能复现原错误的针对性验证，候选稳定后只执行适用的正式回归。测试不能继续用无条件模拟成功掩盖真实失败依赖。例行每日完整专项和正式生产门槛仍按原合同执行；同轮相同适用条件已通过的专项不重复。局部修复验证不能冒充当日例行门槛通过。

## 3. 以依赖与哈希判定复用

读取既有证明实际绑定的日期、运行/测试源码、consumer、配置/依赖、authority、输入及产物哈希、检查版本和运行环境。相关值变化时，只失效实际受影响阶段及下游；无关文件/文档提交不能自动使行情、历史和全部测试失效。不能只凭“HEAD 不同”或“路径相同”作决定。

跨源码复用只能经已有正式兼容/认证入口或可审核的最小适配，保留原包作者、源码、日期和哈希。不能手改 manifest、指纹或回执，把旧包冒称新源码生成。新源码若确实要求新匹配包，只重建其依赖闭包，并说明哪些旧证据仍有效。

接收方仍核对真实落盘的字节、完整清单、日期、来源和最终字段。发送方检查通过不能免除接收方必要校验；重复检查也不应自动变成重复下载或计算。

## 4. 先保留成果，再进入易丢失的长阶段

在临时云端任务进入下一个昂贵阶段前，确认已完成成果有实际可恢复的官方工件或检查点。优先复用现有完整包、来源回执和增量清单；不要为每个小步骤再复制整套历史。检查点只记录必要的阶段状态、输入/输出哈希、来源 run、命令、起止时间、退出码和原日志；不含凭据。

失败时保留已完成工件与失败原文。部分缓存/检查点必须明确标为未完成，不得冒充完整包、生产日历、当日新鲜度或发布许可。恢复前核来源、身份、完整性、日期和 owner，并继续原生数据校验。

现有程序不支持阶段恢复时，先评估是否可用最小、可验证的续接解决。确实无法复用时，写清“哪部分丢失或失效、为什么、必须重跑哪一段”；不得把整条重跑当默认动作，也不得用跳过门槛假装已有恢复能力。本规则本身不代表运行程序已实现检查点恢复。

## 5. 只交付一次，分别验收

结果已正确而只有展示失败时，只重渲染。报告已正确而只有发送失败时，只处理发送阶段；如平台原正式入口仍强制重算，明确记录这一限制，不能私自绕过原发送门禁。用户授权的正常重发沿用原正常通道和去重事务。

分别核实代码修复、当日策略结果、完整包、SMTP 接受、完成标记和 INBOX。已送达的日报不重复发送；intent 状态不确定先查证。两策略独立成败，另一条成功结果不重复重算。

适用门槛通过且用户要求的交付完成后结束。额外审计、压测、优化和历史重算仅按用户当前明确范围执行；不因日报完成自动恢复延期事项。
