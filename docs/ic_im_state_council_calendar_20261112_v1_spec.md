# 国务院假期推导交易日历 v1（2026-11-12）

状态：用户已授权采用国务院颁布假期推导交易日历；先完成日历，再对全部修订进行多智能体对抗审计。仅本地实施，生产采用另按原发布合同。

## 规则与证据

- 决策日自2026-11-12起，2027年接受国务院办公厅2026-11-05发布的2027年节假日通知，结合周六、周日休市推导。周末调休上班仍不交易。
- 已有交易所核验年度继续优先使用原休市表，不改2022—2026历史日期，特别保留2024-02-09等交易所额外休市。
- 区分“国务院官方假期来源、用户批准的推导日历”与“交易所已确认”；推导日历可用于研究日期、信号及账本续接的日历门槛，明确记录来源、政策版本和哈希，不伪称交易所确认。
- 只接受已登记2027年来源，不外推2028或其它年度。来源缺失、哈希不符、格式损坏仍失败关闭。
- 2026-11-12之前的历史回放按当时日历政策处理；旧规格、旧信号、正式账本、已发送日报及此前首次验收记录不改写。
- 主机直连来源失败时保留原错误。保存检索服务实际返回的政府通知文本快照，标明取得方式与文本SHA，不把检索文本SHA称为原网页字节SHA。
- 实际挂牌合约集合、行情日期、采集时钟和成交证据门槛继续独立核验。日历不制造挂牌、报价或账户成交。

## 实施

- 新增小型日历来源适配器和有哈希绑定的数据文件；原交易所年份常量不混入推导年份。
- 更新交易日、到期日顺延、跨年下一交易日及消费目标的日历检查；缺交易所年度公告不再单独阻塞已批准推导年度。
- 信号携带推导日历的明确来源与政策元数据；新交付及持久化入口重验元数据，不能仅伪造persistence_eligible或calendar_provisional绕过。
- 保留现行策略阈值、仓位、Put/Call规则、30%绩效保证金口径、来源时钟和每日唯一writer。

## 验证与后续审计

- 修改前备份主脚本、状态验证器和被更新测试，登记正式账本及冻结文件哈希。
- 验证2027全部假期、调休周末、跨年和期权顺延；以2026政府通知推导结果对照既有交易所日历逐日比较，并验证2024额外休市优先级。
- 反例覆盖缺来源、篡改、未知年度、政策生效前回放、缺元数据及伪造交易所确认。
- 日历实施及必要边界验证完成后，固定全套源码交给独立智能体审计；各智能体只读生产源码，在隔离目录保存反例。修复由主协调统一处理，最后按受影响闭包复验。
